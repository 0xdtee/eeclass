# eeclass 开源同类项目调研报告

> 调研日期：2026-10-01
> 范围：GitHub 上与 eeclass 有重叠的开源项目，共四类：① 实时转写、字幕与说话人分离引擎；② 会议助手和 AI 笔记产品；③ 课后学习、知识库与教学 AI；④ 讲座录制与 LMS 生态。
> 说明：Star 数是调研当天的近似值。标 **[未核实]** 的项目，没有在一手页面确认过。所谓"已有能力"，是对照 eeclass 当前代码（`backend/service/*`、`frontend/src`）核对过的。

---

## 0. 结论速览

1. **还没有开源项目把 eeclass 的整套能力做全**：课堂现场实时字幕、声纹库、板书时间轴、课表日历、教材对照总结、课程级考点和模拟卷、Word 插件和 iPad 端，eeclass 都有。形态最接近的是 **Speakr**（自托管转写笔记平台）和 **WhisperLiveKit**（自托管实时转写和同传服务），但两者都没有面向课堂的学习闭环。
2. **竞争压力主要来自课后 AI 这一侧**。open-notebook（约 3.97 万星）、SurfSense、DeepTutor、OpenMAIC 在 2025–2026 年涨得很快，已经覆盖了"总结、闪卡、测验、问答、播客"这类功能。eeclass 的护城河应该放在**课堂现场采集、中文与 CPU 部署、课程结构化**上。
3. **最值得吸收的六件事**（性价比从高到低）：
   - **FSRS 替换艾宾浩斯**：小改动，收益明确。
   - **2pass 识别**：实时草稿加句尾定稿，同时拿到流式的低延迟和 SenseVoice 的准确率。
   - **热词与纠错三层化**：识别时偏置、识别后模糊同音替换、词表从课件自动抽取。
   - **问答带可点击引用，并做混合检索**：引用可跳到音频时间戳、教材页或板书，检索做跨课次的向量加全文检索。
   - **扫码多端看实时字幕**：对听障和外语学生、投屏场景很有用。
   - **字幕 SRT/VTT 导出、开放 API、MCP Server**。

## 2. 重点项目详解

### 2.1 实时转写与说话人分离

#### WhisperLiveKit：[QuentinFuxa/WhisperLiveKit](https://github.com/QuentinFuxa/WhisperLiveKit)
- 约 1.1 万星，Apache-2.0，很活跃。一个自托管服务里集成了流式识别、说话人分离、同传和 Web UI，是和 eeclass 技术形态最像的项目。
- 可选后端：SimulStreaming（AlignAtt）、WhisperStreaming（LocalAgreement）、SenseVoiceSmall、Qwen3-ASR、Voxtral。
- **可借鉴**：
  - WebSocket 的 `?context=` 参数：每场会话注入术语和人名，对应 eeclass 的"本课程词表"。
  - `?mode=diff` 增量协议：只推送变化的部分，iPad 端省流量也省渲染。
  - 兼容 OpenAI `/v1/audio/transcriptions` 和 Deepgram 风格接口，第三方工具不用改就能接入。
  - 说话人分离默认改用 Streaming Sortformer，diart 已被它标为不推荐。

#### FunASR：[modelscope/FunASR](https://github.com/modelscope/FunASR)
- 约 2.06 万星，MIT。中文工业级全家桶：Paraformer 流式和离线、fsmn-vad、ct-punc、cam++、ITN、热词、时间戳。
- **可借鉴**：
  - **2pass 模式**：先用流式模型出实时草稿；VAD 判定句末后，再用离线模型重识别整句并加标点，覆盖掉草稿。eeclass 现在在 zipformer（首字约 0.6s，但不够准）和 SenseVoice（准，但按句出）之间只能二选一，2pass 可以兼得两者的长处。
  - SeACo-Paraformer **带权热词**（`"关键词 20"`），在识别阶段就做偏置，比事后替换更早介入。

#### Fun-ASR-Nano / Qwen3-ASR
- **Fun-ASR-Nano**（[QwenAudio/Fun-ASR](https://github.com/QwenAudio/Fun-ASR)，Apache-2.0）：LLM 型 ASR，支持中英日和 7 大方言，带热词和字级时间戳。sherpa-onnx 1.13.8 已经支持它，并修复了静音段幻觉问题。有第三方 CPU 测试：20 秒音频约 2 秒处理完，**适合作为 2pass 的第二遍定稿模型**。
- **Qwen3-ASR**（[QwenLM/Qwen3-ASR](https://github.com/QwenLM/Qwen3-ASR)，Apache-2.0）：支持 30 种语言和 22 种方言。随附的 **Qwen3-ForcedAligner-0.6B** 可以做任意粒度的强制对齐，可用于课后字级重对齐，让"点字跳音频"和课件同步更准。它的官方流式推理依赖 vLLM 和 GPU，所以在 CPU 上只适合离线定稿。

#### sherpa-onnx：[k2-fsa/sherpa-onnx](https://github.com/k2-fsa/sherpa-onnx)（eeclass 的底座）
近期版本里有几项可以直接用：
- **HomophoneReplacer（拼音词组匹配替换）**：在识别器内部基于 lexicon 和 FST 做同音替换，可以补充或替代 `term_fix.py`。
- **transducer 热词**：在 `modified_beam_search` 下通过 `hotwords_file` / `hotwords_score` 做偏置，可以直接加到现有的流式 zipformer 上（参数名 **[未核实]**，接入前请对照文档）。
- 输出 JSON 暴露了 `num_trailing_blanks`，可以用来自定义断句，代替靠时长硬切。
- 离线说话人分离会给出每段置信度，可以用来把低置信的段落回退为"未知说话人"。
- 支持 Intel NPU（OpenVINO）。

#### SimulStreaming：[ufal/SimulStreaming](https://github.com/ufal/SimulStreaming)
- MIT，IWSLT 2025 同传最佳系统，已取代 whisper_streaming。
- **可借鉴**：
  - **LocalAgreement-2**：连续两次解码的公共前缀才提交。用于滑窗重识别时稳定 partial 结果，避免字幕闪动。
  - **只翻译已提交的稳定前缀、输出只追加**的同传策略。
  - 把术语表放进翻译提示词。

#### CapsWriter-Offline：[HaujetZhao/CapsWriter-Offline](https://github.com/HaujetZhao/CapsWriter-Offline)
- 约 6.9k 星，MIT，Windows 离线语音输入工具。
- **可借鉴**：
  - **音素模糊匹配热词**：相似度超过阈值就替换。eeclass 的 `term_fix.py` 要求逐字拼音完全一致，所以前后鼻音、平翘舌、错一个字都会漏掉。
  - 正则规则替换表。
  - 中文数字 ITN，例如"十五六个"转成"15~16个"。

#### pyannote-audio 4 / Community-1：[pyannote/pyannote-audio](https://github.com/pyannote/pyannote-audio)
- MIT。它把聚类方法换成了 VBx，说话人计数更准。
- **exclusive diarization（排他式说话人分离）** 保证每个时刻只归属一个说话人，和 ASR 时间戳合并时很方便。可以用来**课后重算说话人**，再用声纹库给说话人命名。

#### 其他参考
| 项目 | 可借鉴点 |
|---|---|
| WhisperX（2.43 万星） | 词级强制对齐加说话人合并的离线后处理范式 |
| Kyutai delayed-streams | "语义 VAD"：按语义判断一句话有没有说完，而不只看静音时长（只支持英法） |
| LiveTranslate | 用 Silero VAD 自适应静音阈值，LLM 译文逐字流式显示 |
| TMSpeech | 基于 sherpa-onnx 的中文字幕。插件协议很轻：stdout 单换行表示更新当前句，双换行表示定稿 |
| NeMo Streaming Sortformer / multitalker-parakeet | 在线说话人缓存，"先分离再识别"处理重叠语音（需要 GPU，中文支持有限） |
| Moonshine | iPad 端侧识别的参考（许可证是自定义的，需要确认） |

### 2.2 会议助手与 AI 笔记产品

#### Speakr：[murtaza-nasir/speakr](https://github.com/murtaza-nasir/speakr)（形态最接近）
- 4k+ 星，AGPLv3 加商业授权双许可，Flask + Vue3 + PostgreSQL，很活跃。
- **可借鉴**（按价值排序）：
  - 摘要 prompt 可以**按录音、标签或文件夹分别配置**，对应 eeclass 的"按课程类型（理工、文科、研讨、实验）切换模板"。
  - **单条录音对话，回答带时间戳引用**；**全库语义检索**（Inquire Mode）。
  - **从内容中提取事件**：比如作业截止日期，可以导出成日历事件，正好接上 eeclass 的日历。
  - **OIDC 单点登录**，可以对接学校统一认证。
  - **REST API + Swagger**、**签名 webhook**。
  - **按账号的 LLM token 预算**，控制 DeepSeek 费用。
  - **保留期自动删除**，满足隐私合规。
  - **浏览器标签页音频采集**，适合网课。
  - 录制时**边录边上传**，刷新页面也不丢。

#### Meetily：[Zackriya-Solutions/meetily](https://github.com/Zackriya-Solutions/meetily)
- 约 3.1 万星，MIT，Tauri + Rust。
- **可借鉴**：
  - **麦克风和系统音频混合采集**，用于腾讯会议或 Zoom 上的网课。
  - Ollama 本地 LLM。eeclass 的 LLM 调用已经是 OpenAI 兼容的 `base_url`，接 Ollama 主要是测试和文档上的工作。
  - Tauri 离线桌面端：断网也能转写，联网后再同步。
- 它把自定义模板、DOCX 导出、团队部署放在 PRO 付费版里，而 eeclass 开源版已经全部具备，这一点可以作为宣传卖点。

#### Anarlog（原 Hyprnote / Char）：[fastrepl/anarlog](https://github.com/fastrepl/anarlog)
- 约 9.4k 星，MIT。
- **可借鉴**：
  - **内置 MCP server 和 CLI**，让 Claude 或 Cursor 能直接查询课堂记录。
  - **Markdown/Obsidian 风格导出**，数据可以随时带走。
  - 转写模型和总结 LLM 分开配置。

#### OpenWhispr、Natively、Amurex、Ecoute
- **OpenWhispr**：检测到 Zoom、Teams 等通话开始后**自动开录**。
- **Natively**：场景模式，内置 Lecture、Seminar 等 persona，按场景切换 prompt。
- **Amurex**：**"迟到回顾"**，迟到的学生一键看到前 15 分钟讲了什么。
- **Ecoute**：麦克风标为"我"，系统音频标为"对方"，分两轨，网课里可以区分教师和远端学生。

#### 会议机器人：Vexa / Attendee
- **Attendee**（[attendee-labs/attendee](https://github.com/attendee-labs/attendee)）：**按日历定时让机器人入会**，提供 webhook，有双向音频（可以用 TTS 在会中播报译文）。
- **Vexa**（[Vexa-ai/vexa](https://github.com/Vexa-ai/vexa)，Apache-2.0）：机器人加入 Meet、Teams、Zoom、Jitsi，通过 WebSocket 实时推送带说话人的转写；提供 MCP；可以把会议沉淀成 Markdown 知识库；支持 air-gapped 部署。
- 对 eeclass 的意义："会议翻译"页和在线课程不再依赖本机采集，**按课表到点自动入会录制**。

#### Scriberr、Whishper
- **Scriberr**：**监听文件夹自动处理**，讲台电脑或录播系统落盘的文件会自动转写并生成笔记。还有 PWA 安装和转写批注。
- **Whishper**：字幕编辑器带 **CPS（每秒字符数）超标警告**，可以拆分或插入段落，支持 **SRT/VTT/JSON/TXT 导出**，用 LibreTranslate 做本地翻译兜底。

### 2.3 实时字幕与无障碍

#### OpenCaptions：[carraroesteban/opencaptions](https://github.com/carraroesteban/opencaptions)
项目很小（约 1 星），但功能设计和 eeclass 的投屏、会议翻译几乎一一对应，值得逐项参考：
- **扫二维码进入房间，选择语言**，用手机看实时字幕。
- 字号和深浅色可调，原文和译文双栏。
- **"我错过了什么？"一键摘要**，以及"向本场提问"。
- 下载 TXT/SRT/VTT，收听译文语音。
- 可打印的二维码海报，多房间运营看板。

#### OBS LocalVocal：[royshil/obs-localvocal](https://github.com/royshil/obs-localvocal)
- 约 1.6k 星，GPL-2.0。
- **可借鉴**：
  - 字幕通过 RTMP 推送到直播流（B 站、YouTube）。
  - 作为 OBS 文本源叠加字幕。
  - 输出 `.srt`。
- 对 eeclass 来说，最低成本的做法是提供一个 **OBS 浏览器源 URL**（透明背景的字幕页），老师用 OBS 录课时就能自带字幕。

#### 课后字幕精修流水线
VideoLingo（约 1.85 万星）用 LLM **重新断句并对齐双语字幕**，然后导出。eeclass 可以借这个思路做课后字幕精修，再加上外语课的配音版（pyVideoTrans）。

#### 无障碍要点（行业惯例）
- 字幕样式自定义：字号、背景不透明度、行数、位置。
- 直播流嵌入 CEA-608/708 字幕。
- 把字幕延迟作为一项体验指标来监控。

### 2.4 课后学习、知识库与教学 AI

#### open-notebook：[lfnovo/open-notebook](https://github.com/lfnovo/open-notebook)
- 约 3.97 万星，MIT，开源版 NotebookLM。
- **可借鉴**：
  - **1–4 人播客式"Audio Overview"**：可以做成"本节课 10 分钟音频复习"，通勤路上听。
  - **Transformations**：用户可以自定义 prompt 模板，批量处理资料。eeclass 现有的单课总结、教材总结、考点预测、模拟卷，可以统一抽象成可配置的模板，并开放给用户自定义。
  - 全文检索加向量检索；提供 MCP Server；支持 18 家以上的模型提供方。

#### SurfSense：[MODSetter/SurfSense](https://github.com/MODSetter/SurfSense)
- 约 1.63 万星。同一份资料可以生成很多种产物：总结、报告、闪卡、测验、**思维导图**、pptx/docx、播客、信息图。
- **可借鉴**：
  - 导出 **pptx 复习讲义**和**思维导图**。
  - "完全离线"的定位，适合对隐私敏感的学校。

#### Kotaemon / RAGFlow
- **Kotaemon**：答案里的**引用可以点击，点开后高亮原文**；检索用混合检索加 rerank。对应到 eeclass，就是引用一点击就跳到转写时间戳、教材页码或板书照片。
- **RAGFlow**（约 9.16 万星）：DeepDoc 版面解析，**按模板分块**（教材、试卷、问答），分块结果可视化，也可以手动修改。可以作为教材接入的参考或后端。

#### LightRAG / GraphRAG
从整个学期的转写和教材中抽取实体与关系，构建**课程知识图谱**，用于：
- 结构化的全课程大总结，比层层拼接摘要更好。
- 知识点依赖图。
- 定位学生的薄弱点。

#### DeepTutor：[HKUDS/DeepTutor](https://github.com/HKUDS/DeepTutor)
- 约 4.06 万星，Apache-2.0。
- **可借鉴**：
  - **Mastery Path（掌握度路径）**：测验结果驱动复习路径，过了掌握度门槛才进入下一个知识点。
  - 带答案和解析的题库。
  - 引用可以验证。

#### OpenMAIC：[THU-MAIC/OpenMAIC](https://github.com/THU-MAIC/OpenMAIC)
- 约 3.97 万星，MIT，清华出品。AI 老师可以在白板上画图、推公式，并用 TTS 讲解；能导出 pptx 和 MP4；已经集成了 FunASR 和 DeepSeek。
- **可借鉴**：把一节课的转写和板书**重新生成为"AI 补课"**，给缺课或没听懂的学生用。

#### 讲课转笔记的直接竞品（都很小）
- **lecture2notes**：对视频帧做幻灯片分类，再对幻灯片做 OCR，与转写合并成摘要。
- **LecturePack**（2026 公测）：**检测幻灯片切换，把转写对齐到每页**；"Ask"的回答附带原文转写片段；有掌握度追踪。
- **lecture-note-app**：FastAPI + React + PG，**课中增量生成笔记**，定位和 eeclass 几乎一样。

#### 间隔重复：FSRS
- 相关仓库：[open-spaced-repetition](https://github.com/open-spaced-repetition)，包括 py-fsrs、ts-fsrs（MIT）。
- FSRS 已经是 Anki 的默认调度算法。它按 Again/Hard/Good/Easy 四档评分，并且可以用学生自己的复习记录优化参数。
- eeclass 现在的 `ReviewTab.tsx` 用的是**艾宾浩斯固定间隔**，换成 ts-fsrs 改动很小。
- 可以顺带做：
  - **填空卡（cloze）**。
  - 用 embedding 去掉重复的卡片。
  - 用 genanki **导出 `.apkg`**，学生可以导入 Anki。

#### 文档与 OCR
| 用途 | 推荐 |
|---|---|
| pptx/docx 课件转 Markdown | MarkItDown（MIT，轻量） |
| 扫描版或公式多的教材 | MinerU（中文和公式最好，许可证需确认）或 docling（MIT），并**保留页码锚点**，这样引用能精确到页 |
| 板书照片 | PaddleOCR 识别文字，UniMERNet 识别公式（真实拍摄场景），生成可检索的 LaTeX |
| 课表截图 | 用视觉语言模型（Qwen3-VL / MiniCPM-V）直接输出结构化 JSON |
| 思维导图 | 让 LLM 输出 Markdown 大纲，再用 markmap（MIT）渲染，大约半天工作量 |
| 播客复习 | podcastfy 式双人脚本，配 CosyVoice（Apache-2.0）中文 TTS |

### 2.5 讲座录制与 LMS 生态

- **Opencast**：高校主流的开源讲座录制平台。工作流里内置 Whisper 和 Vosk 转写节点，有 Moodle 插件，支持 LTI 1.3。
- **BigBlueButton 3.x**：字幕已插件化。可以借鉴**每个用户各自选择字幕语言**。
- **Jitsi**：字幕叠加在画面上，同时在 CC 面板里留一份滚动记录。Jigasi 转写方案将被弃用。
- 对 eeclass 的意义：**实现一个 LTI 1.3 工具，就能接入 Moodle、Canvas、Blackboard 等 LMS**，这是进入学校的标准通道。也可以把 eeclass 定位成 Opencast 的"实时字幕 + AI 笔记"补充组件。

## 3. 对照 eeclass 现状的差距分析

| 能力 | eeclass 现状 | 业界做法 | 差距 |
|---|---|---|---|
| 流式识别 | zipformer 流式，或 SenseVoice 按句识别，二选一 | 2pass：流式草稿加句末离线定稿（FunASR） | **中** |
| 识别时热词 | 只有 whisper 后端有 `hotwords`，本地 zipformer 和 SenseVoice 没有 | transducer 热词、SeACo 带权热词、会话级 context | **中** |
| 同音纠错 | `term_fix.py`：逐字拼音完全一致才替换 | 音素模糊匹配加阈值，FST HomophoneReplacer，正则规则 | **中** |
| 断句 | VAD 加时长上限 | `num_trailing_blanks`、自适应静音阈值、语义 VAD | 小 |
| 说话人 | 3D-Speaker 实时声纹，GPU 重叠分离为可选项 | 课后用 pyannote Community-1 exclusive 重算，带置信度门限 | 小 |
| 时间对齐 | 句级 | 字级强制对齐（Qwen3-ForcedAligner、CTC 时间戳） | 小 |
| 复习调度 | 艾宾浩斯固定间隔 | FSRS | **大（且容易补）** |
| 问答 | 单课全文塞进 prompt | 跨课次 RAG，引用可点击跳转 | **大** |
| 检索 | 关键词全文检索 | 全文加向量混合检索，再 rerank | **中** |
| 字幕导出 | PDF / docx | SRT / VTT，带 CPS 校验的字幕编辑器 | **中（容易补）** |
| 多端看字幕 | 分享链接是只读的事后查看 | 扫码进房间，实时多语言字幕 | **中** |
| 开放接口 | 无 | REST API、webhook、MCP server | **中** |
| 网课采集 | 麦克风 | 系统音频或标签页采集，机器人入会，日历触发 | **中** |
| 课后产物 | 总结、考点、模拟卷、闪卡、测验 | 还有思维导图、播客、pptx 讲义、知识图谱 | 小到中 |
| LLM | DeepSeek（OpenAI 兼容 `base_url`） | 多家 provider、Ollama 本地模型、token 预算 | 小 |
| 学校对接 | 邮箱注册 | OIDC 单点登录、LTI 1.3 | **中** |

## 4. 建议路线图

### P0：小投入、收益明确（1–2 周内）
1. **复习调度换成 FSRS**：前端接 ts-fsrs，评分改为四档，保留现有卡片数据，迁移时把旧卡片当新卡处理。
2. **SRT / VTT 导出**：现有数据里已经有逐句的时间和译文，可以直接输出双语字幕。
3. **热词模糊匹配**：在 `term_fix.py` 上加一档"拼音编辑距离 ≤ 1，或平翘舌、前后鼻音等价"的匹配。只对已登记的术语生效，并保持"绝不丢字"的约束。
4. **课件关键词自动进词表**：从已上传的课件和课程名里抽取术语，按会话注入。
5. **思维导图**：在单课总结里让 LLM 额外输出 Markdown 大纲，前端用 markmap 渲染。

### P1：核心体验提升（1–2 个月）
6. **2pass 识别**：zipformer 出 partial，句末用 SenseVoice 或 Fun-ASR-Nano（sherpa-onnx）定稿替换。滑窗重识别时配合 LocalAgreement 稳定前缀，前端用 diff 协议增量更新。
7. **跨课程 RAG 问答，引用可点击**：
   - 转写按句或按段做 embedding，用 PostgreSQL 的 pgvector 存储，和现有全文检索混合，再做 rerank。
   - 回答里的引用可以跳到音频时间戳、教材页或板书照片。
8. **扫码看实时字幕**：教师端生成二维码，观众端选择语言、调字号，有"我错过了什么"摘要，支持投屏或 OBS 浏览器源。
9. **按课程类型配置摘要模板**：参考 open-notebook 的 Transformations 和 Speakr 的标签级 prompt，允许用户编辑。
10. **教材接入升级**：用 MinerU 或 docling 解析 PDF 并保留页码锚点，让"【教材】"标注精确到页。

### P2：扩展场景与生态（季度级）
11. **开放 API、签名 webhook、MCP Server**：让 Claude Desktop 等客户端可以直接查询课程库。
12. **网课采集**：浏览器标签页或系统音频采集；按课表定时自动开录；参考 Attendee 做在线会议机器人。
13. **音频复习播客**：生成双人对话脚本，配 CosyVoice 中文 TTS。
14. **课后说话人重算**：pyannote Community-1 exclusive 模式加声纹库命名，低置信段落标为"未知"。
15. **掌握度路径和知识图谱**：用 LightRAG 抽取知识点依赖；测验结果驱动复习，参考 DeepTutor。
16. **学校对接**：OIDC 单点登录、LTI 1.3、保留期自动删除、按账号的 LLM token 预算。
17. **板书公式 OCR**：PaddleOCR 加 UniMERNet，让板书公式可以检索；课表截图改为视觉模型直接输出结构化结果。
